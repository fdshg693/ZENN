# 既存ZENN記事の改善
以下の点を中心に、既存のZENN記事を改善してください。

## 改善の観点

### 誤字脱字の修正
- 文言の統一（技術記事らしく固く）
- 矛盾点の発見・解消
- メタ表現の削除（作者目線のメモや文言が残存していないか）
- 英語の引用文で、日本語訳や要約がない場合は、翻訳や要約を追加する

### リンクの修正
- 別記事への参照が相対パスで`./ファイル名`の形になっていなければそうする
  - 一時的なフォルダ構造の都合で`./ファイル名`で表すとパスが現状は合わないとしても、ZENNで公開する際には、必ず`articles`フォルダ直下にフラットに配置されることを想定して、参照を修正してよい
- このレポジトリ内の他のファイル（articlesフォルダ内同士の関係でない場合）は、`https://github.com/fdshg693/ZENN/blob/main/ファイルのパス`の形で絶対URLで参照する
  - ZENN記事からの参照なので、相対パスは使えないため。ZENN記事同士の参照は、前のルールで相対パスにすること。

### 図解の修正
- ASCII図を使っている箇所があれば、Mermaid記法にする
  - わざわざ、Mermaidに置き換える必要がない単純な図、あるいはMermaidが向かない図などはASCIIのままでよい

## 改善フロー
改善の仕方は以下のようにしてください
**サブエージェントを使うことで、常にフレッシュな視点を持って評価させてください。サブエージェントは速度・精度の両立の観点からsonnetを推奨します。**

1. サブエージェントに、上記の観点で記事を評価させる
- メタ表現の発見などは非常に困難なので、セッションを分けて、適切なスコープで必要に応じて複数セッションを用いてサブエージェントに評価させることを推奨します
2. サブエージェントの評価をもとに、記事を改善する
3. 改善した記事を再度サブエージェントに評価させる
4. サブエージェントの指摘が少ない、または些細になってきたところで、ユーザーにこれくらいの改善で問題ないか確認する
- サブエージェントの指摘が多くない限り、最大2ループ程度でユーザーに確認することを推奨します
