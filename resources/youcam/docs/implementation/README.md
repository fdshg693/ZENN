## 記述テンプレート（全機能共通）

機能間で同じ目線で追えるよう、各ファイルは**同じ見出し構成**で書く。
テンプレートを固定することで「この機能はどのファイルを触り、どこで詰まりやすいか」が一定の場所で見つかる。

| 見出し | 何を書くか |
| --- | --- |
| **目的 / スコープ** | PLAN の「提供する / 提供しない」を実装の言葉で再掲。やらないことを明示して肥大化を防ぐ。 |
| **担当ファイル** | 触るファイルとレイヤ（全体設計[セクション3](../implementation-plan.md#3-ディレクトリ--ファイル構成)の構成に対応）。 |
| **データ（型）** | この機能が扱う状態・APIペイロードの型。仕様の正本。 |
| **処理フロー** | API/ドメインでの具体的な手順（呼ぶ順・分岐）。 |
| **UI** | コンポーネントの責務と操作。 |
| **つまりどころ** | この機能固有の落とし穴と、それをどのファイルで吸収するか。 |
| **完了条件** | 「動いた」と言える観測可能な状態（動作確認の基準）。 |
