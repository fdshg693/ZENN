# この POC の価値分析

「YouCam API そのものの価値」と「この POC（化粧ルーティンをブロックで繋いで保存・共有・ドライラン）が
その上に足す価値」を分けて考える。調査日: 2026-05-23。

> 結論を先に: API 単体の差別化は **realism（描画品質）と enterprise 向け** に寄っている。
> この POC の独自性は **API がカバーしていない「ルーティン＝手順の合成・保存・共有」というワークフロー層** にある。
> ただしそれは技術的に難しいというより、**「誰の・どんな課題を解くか」を決め切れるか** に価値が掛かっている。

---

## 1. 前提: ベースの API（YouCam）はどこが強いか

競合（Banuba / ModiFace(L'Oréal) / DeepAR / GlamAR）と比べた YouCam=Perfect Corp の立ち位置（出典は末尾）:

- **描画リアリズムと肌診断が強み。** HD AI Skin Analysis（皮膚科医監修レベルの多項目診断）は学習データ的に他社が再現しにくい、と評される。
- **ブランド中立 × 巨大な事前デジタル化カタログ。** 800+ ブランド連携で、既存コスメ SKU を色・質感まで再現したパターン資産を持つ。
- **エンタープライズ寄り。** 調達・法務・コンプラのフローが大手化粧品コングロマリット向けに作られている＝**小規模/短納期チームには重い**、という評価。
- 競合の住み分け（同調査の要約）:
  - Banuba: フルスタックの makeup AR SDK、オンデバイス処理、フラット課金、2週間で導入 → 自前アプリを作るチーム向け
  - ModiFace: L'Oréal 系列。リップ描画は最高クラスだが L'Oréal の世界観に閉じる
  - GlamAR: SMB 向けの軽量モジュラー SaaS

→ **API レベルの「できる/できない」では大差がつきにくい**（試着・診断は各社できる）。差は realism・カタログ・課金体系・ロックインの有無。

## 2. この POC は「通常アプリ・API ではしにくい何」を提供できているか

ここが本題。**個々の API 機能** ではなく、**それらを束ねるワークフロー** に注目すると差が出る。

### (A) API 単体だと素直に作りにくいこと = POC が埋める空白

1. **複数操作の「手順」としての合成・連結**
   - YouCam API は基本 **1機能=1タスク** の単位（makeup-vto / skin-analysis / hairstyle …）。
   - 「肌診断 → ベースメイク → ポイントメイク → ヘア」のような **横断ルーティン** は API 標準フローには無い。
   - これは `dst_id` チェイン（[api-basics.md](./api-basics.md)）で技術的には可能だが、**「手順の組み立て・保存・再生」というモデルは自分で作る必要がある**。← POC の主戦場。

2. **設定の「再利用可能な資産化」(共有)**
   - 通常の試着体験は「その場で試して終わり」。**ルーティンを JSON として保存→他人が自分の顔で再生** という発想は、API にもほとんどの実装にも無い。
   - 実装的にも軽い: ルーティン = `effects` 設定 + 使用機能 + template_id の JSON。**ソース画像（顔）だけ差し替えれば誰の手順でも再現できる**（[makeup-vto.md](./makeup-vto.md)）。

3. **API 単体の体験 = 1ショット。POC = ワークフロー/プロセス。**
   - 既存の「VTO プラグイン」は EC のカート横で1製品を試すのが主。**手順の文脈（順番・意図・なぜこの色か）** は表現できない。
   - 「GRWM（Get Ready With Me）」がTikTokで1800億回以上見られている文化（出典）を、**インタラクティブに再現できる形** に落とすのは既存実装の空白。

### (B) 逆に「POC でも難しい/API 依存のまま」なこと（過大評価しないため）

- **描画品質そのもの** は API 任せ。POC では改善できない（むしろ YouCam の強みに乗る形）。
- **動画/ライブ試着**（GRWM の本来の主役は動画）。今回フォーカスした API は静止画ベース。動画は別 API・別コスト。
- **製品との紐付け（買えるリンク）**。本当の社会的・商業的価値は「試した色が買える SKU に対応」だが、これは YouCam のカタログ/ブランド連携側の話で、POC 単体では持てない。
- **APIキーをフロントに置く静的サイト構成** ゆえ、本番運用（鍵秘匿・CORS・課金管理）は別途必要。POC は「価値検証」までが射程。

> まとめ: **「難しい技術」を実装している価値ではなく、「誰もまとめて作っていないワークフロー」を提示する価値**。
> 技術的参入障壁は低い＝裏返すと「アイデアと体験設計の良し悪し」で勝負が決まる、ということ。

## 3. どの層に・どれくらいアピールできそうか

市場は追い風（仮想メイク市場は 2025年 $3.8B → 2034年 $23.4B, CAGR ~21.8%。VTO で返品が最大35%減・出典）。
その上で、このPOCの「ルーティン共有」コンセプトが刺さりやすい順に層を整理する。

| 層 | 刺さり度 | 理由 / フック | 懸念 |
| --- | --- | --- | --- |
| **クリエイター/インフルエンサー（GRWM文化）** | ◎ 高 | 「自分のルーティンを配布物として共有」が刺さる。GRWM=1800億再生の需要に直結。フォロワーが**同じ手順を自分の顔で試せる**のは既存にない体験 | 動画が主戦場なので静止画でどこまで満足されるか |
| **ビューティー教育/メイクスクール・アドバイザー** | ◎〜○ | 「手順」を教材化・処方箋化できる。診断→提案→手順、の流れが商材になる | 精度・信頼性が問われる（医療/肌診断の文脈） |
| **D2C/インディー化粧品ブランド** | ○ 中 | 「このブランドで作る公式ルーティン」を配布しUGCを誘発。エンタープライズ調達が要らない**軽量導入の検証**として価値 | 最終的に「買える」連携が無いと収益化しにくい |
| **EC/小売（既存VTOの代替/補完）** | △〜○ | 返品削減・回遊の文脈はあるが、ここは既存VTOプラグインの主戦場。**「単品試着」ではなく「セット提案/ルーティン提案」** という切り口でのみ差別化 | Perfect Corp 公式・競合と正面衝突 |
| **エンタープライズ大手ブランド** | △ 低 | YouCam 本体/ModiFace が直接握っている層。POC の軽量さは逆に刺さりにくい | 調達/品質要件が重く、POC の射程外 |
| **一般消費者（toC 単体プロダクト）** | △ 低 | 「ルーティン共有SNS」単体での toC は獲得コストが重い。クリエイター経由の方が現実的 | リテンション・ネットワーク効果の壁 |

### 一番アピールできる的（推奨フォーカス）

**クリエイター × ルーティン共有** が最有力。理由:
- 既存 API/アプリが埋めていない空白（手順の合成・配布）に最も素直にハマる。
- GRWM という巨大な既存需要・文化があり、価値の説明が一言で済む（「あなたのGRWMを、フォロワーが自分の顔で再生できる」）。
- 技術障壁が低いことが、この層では弱点になりにくい（バズ/共有が価値の源泉で、描画は YouCam に任せられる）。

## 4. POC として検証すべき仮説（価値を測るための問い）

1. **再現性**: 他人のルーティン JSON を自分の顔に適用したとき、「同じ手順」と感じられる結果になるか（顔が違えば似合いも変わる問題）。
2. **共有の摩擦**: JSON import/export だけで「共有された」と感じてもらえるか。リンク一発が要るか。
3. **静止画の満足度**: 動画 GRWM に対して、静止画ルーティンでどれだけ需要を拾えるか。
4. **チェイン体験の意味**: `dst_id` 連結で「途中経過が見える」ことが、単発一括適用より価値を生むか。
5. **運用前提**: ブラウザ直叩き（CORS）・APIキー入力方式が体験を壊さないか（[README](./README.md) の未確認事項）。

> これらは「作る前に決める」より「最小実装で測る」性質の問い。POC の存在意義はここの検証にある。
