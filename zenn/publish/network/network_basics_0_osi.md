## このシリーズについて

「クラウドの閉域(プライベートネットワーク)を作る」という記事を別途書きました。

- プライベートエンドポイントを作ったのに公開 URL でつながってしまう
- 外向きを塞いだらアプリが起動しなくなった
- ネットワークは正しいはずなのに「名前解決できません」で止まる

——こうした閉域特有のハマりどころを扱った記事です。あの記事は「閉域の作り方」は分かる読者を想定していましたが、本シリーズはその **一段下の前提**、つまり「そもそも NAT とは? CIDR の `/24` は何を意味する? DNS 解決とは何が起きているのか?」を、汎用ネットワークの原理から深く埋めにいきます。

各記事は **①まず汎用原理を深く → ②それが AWS / Azure のどの部品(VPC・サブネット・セキュリティグループ・ルートテーブル・プライベート DNS)に対応するか → ③閉域記事のどこに効くか** という 3 段で進みます。

全 5 本の構成は次の通りです。

0. **パケットの一生 — OSI/TCP-IP モデルで地図を持つ**(この記事)
1. IP アドレス・CIDR・サブネット — 区画を切るとは何か
2. ルーティングと NAT — パケットはなぜ目的地に着くか

4. DNS の仕組み — 名前が引けることとつながることは別

この 0 番では、以降 4 本で使う **座標系**を用意します。

## なぜ「層」に分けるのか

ネットワークの通信は、ひとつの大きな魔法ではありません。**役割の違う処理を何段も積み重ねた結果**です。

- 電気信号やビット列を運ぶ処理
- 隣の機器までフレームを届ける処理
- ネットワークをまたいで目的地まで運ぶ処理
- アプリ同士のデータの順序や再送を面倒みる処理
- 「HTTP でこの URL を取得する」といったアプリの会話

これらを **層(レイヤ)** に分けて考えるのには、実用上の大きな利点があります。**「どこが壊れているか」を局所化できる**のです。

閉域でつながらないとき、闇雲にあちこち触るのではなく「DNS は引けているか → 経路はあるか → ファイアウォールは通しているか」と層の順で潰していく——これは後の記事 4 で扱う閉域記事の「切り分けの順番」そのものですが、その発想の根っこが「通信は層でできている」という事実です。

## OSI 7 層モデルと TCP/IP モデル

層を整理した最も有名な枠組みが **OSI 参照モデル**です。下から順に 7 層あります。

| 層 | 名前 | ざっくりの役割 | 代表例 |
|----|------|--------------|--------|
| L7 | アプリケーション層 | アプリ同士の会話 | HTTP, **DNS** |
| L6 | プレゼンテーション層 | 文字コード・暗号・圧縮 | TLS(の一部), 文字エンコード |
| L5 | セッション層 | 会話の開始・維持・終了 | セッション管理 |
| L4 | トランスポート層 | 端から端への配送・順序・再送 | **TCP / UDP** |
| L3 | ネットワーク層 | ネットワークをまたぐ配送 | **IP**, ルーティング |
| L2 | データリンク層 | 隣接機器へのフレーム配送 | Ethernet, **MAC アドレス** |
| L1 | 物理層 | ビットを電気/光/電波で運ぶ | ケーブル, 電気信号 |

一方、実際のインターネットの実装が従うのは **TCP/IP モデル**で、こちらは 5 層に簡略化されています。OSI の L5(セッション)と L6(プレゼンテーション)を L7(アプリケーション)に吸収した形です([GeeksforGeeks: OSI and TCP/IP Model](https://www.geeksforgeeks.org/computer-networks/difference-between-osi-model-and-tcp-ip-model))。

実務では、この 2 つを混ぜて「L3 の問題」「L4 で見ている」「L7 のヘッダ」のように層番号で会話します。本シリーズで掘る対象を層番号で言うと——

- 記事 1(IP・CIDR・サブネット)= **L3**
- 記事 2(ルーティング・NAT)= **L3**
- 記事 3(ファイアウォール: ポート/TCP/UDP)= **L3〜L4**
- 記事 4(DNS)= **L7**(ただし閉域の要)

——となります。「閉域でつながらない」原因は、たいていこの L3・L4・L7 のどこか一層に局在しています。

:::message
L1/L2(物理・データリンク)は、クラウドでは事業者が抽象化してくれており、利用者が直接触ることはほとんどありません。本シリーズが L3 以上を厚く扱うのはこのためです。とはいえ「フレームと MAC は L2」「IP は L3」という対応は、後で出てくる「ルータは IP を見て中継する」を理解する土台になります。
:::

## カプセル化 — データが層を降りていく

層モデルで一番大事な動きが **カプセル化(encapsulation)** です。

アプリが送りたいデータは、下の層に渡されるたびに、その層のヘッダ(と L2 ではトレーラ)で包まれていきます。手紙を封筒に入れ、それをさらに大きな封筒に入れていくイメージです。

```
[アプリのデータ]
        ↓ L4 がヘッダを付ける(送信元/宛先ポートなど)
[TCPヘッダ][アプリのデータ]                 ← これを「セグメント」と呼ぶ
        ↓ L3 がヘッダを付ける(送信元/宛先IPなど)
[IPヘッダ][TCPヘッダ][アプリのデータ]        ← これを「パケット」と呼ぶ
        ↓ L2 がヘッダ/トレーラを付ける(送信元/宛先MACなど)
[Ethernet][IPヘッダ][TCPヘッダ][データ][FCS] ← これを「フレーム」と呼ぶ
        ↓ L1 がビット列として送出
```

各層でできあがる単位には名前が付いており、**L4 = セグメント、L3 = パケット、L2 = フレーム**です([Study CCNA: Encapsulation](https://study-ccna.com/encapsulation))。OSI の用語では総称して **PDU(Protocol Data Unit)** と呼びます。

受信側では逆向きに、各層が自分のヘッダを読んで外し、中身を上の層へ渡していきます。これが **デカプセル化**です。

### なぜこれを知っておくと得か

ヘッダには「その層が判断に使う情報」が入っています。だから、**機器によって見ている層が違う**のです。

- **スイッチ(L2)** は L2 ヘッダ、つまり **MAC アドレス**だけを見てフレームを中継します。
- **ルータ(L3)** は L2 と L3 を見て、**宛先 IP** をもとに次のネットワークへパケットを転送します([NetworkAcademy.IO: OSI model](https://www.networkacademy.io/ccna/network-fundamentals/understanding-the-osi-model))。
- **ファイアウォール / セキュリティグループ**は、IP(L3)に加えて **ポート番号(L4)** まで見て、通すか弾くかを決めます(記事 3)。

「セキュリティグループは IP とポートで制御できるが、URL のパスでは制御できない」のはなぜか——それは **セキュリティグループが L3/L4 を見る部品で、L7(HTTP のパス)は見ていない**からです。層を意識すると、各部品の「できること/できないこと」の境界が自然に説明できます。

## この地図にクラウドの部品を置いてみる

閉域記事に出てきた登場人物を、層の地図の上に配置すると次のようになります。

| 層 | 汎用概念 | クラウドの部品(例) | 本シリーズの担当記事 |
|----|---------|-------------------|------------------|
| L7 | DNS, HTTP | Route 53 / Private DNS Zone | 記事 4 |
| L4 | TCP/UDP, ポート | セキュリティグループ / NSG / NACL | 記事 3 |
| L3 | IP, ルーティング, NAT | VPC/VNet, サブネット, ルートテーブル, NAT Gateway | 記事 1・2 |
| L2/L1 | フレーム, 物理 | (事業者が抽象化) | — |

「閉域を作る」とは、結局この表の **複数の層をそれぞれ正しく設定すること**にほかなりません。閉域記事が「閉域は単一スイッチではない。4 つの層を別々に設計して初めて閉じる」と書いていたのは、まさにこの多層構造のことを言っていました。

## まとめ

- 通信は役割の違う処理を積み重ねた **層構造**。だから「どこが壊れているか」を層で局所化できる。
- **OSI は 7 層、TCP/IP は 5 層**。実務では層番号(L3, L4, L7…)で会話する。
- データは下の層へ渡るたびにヘッダで包まれる(**カプセル化**)。L4=セグメント、L3=パケット、L2=フレーム。
- **機器によって見る層が違う**。スイッチは L2、ルータは L3、ファイアウォールは L3/L4。これが各部品の「できること」の境界を決める。
- クラウドの閉域は、この地図上の複数の層をそれぞれ設定する作業である。

次の記事では、地図の中心である **L3** に降りて、すべての出発点となる「IP アドレスと、それを区画に切る CIDR / サブネット」を掘ります。「プライベート IP を割り当てた=閉域」という最初の誤解を、原理から解きほぐします。
